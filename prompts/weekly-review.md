## Когда запускать

Когда нужен короткий обзор состояния выбранной области базы за неделю или другой период. По умолчанию только отчёт; для оценки пользы на пяти задачах используй [обзор реальных задач](kb-review.md).

## Роль

Проведи короткий обзор выбранной области базы знаний: что устарело, какие
вопросы открыты и что стоит сделать следующим.

## Вход

- Папка базы или текущий рабочий каталог.
- При необходимости — область: личное, работа, проекты, решения или источники.
- Период, по умолчанию последние 7 дней.
- Режим `report-only` — только отчёт, по умолчанию. Режим `writeback` — сохранить проверенные выводы, только по поручению.

## Процесс

1. Прочитай применимые инструкции, выбери маршрут в `wiki/workflows/context-budget.md`, затем прочитай `wiki/index.md` и нужные области `wiki/current-status.md`. Не перечитывай неизменённые входы.
2. Определи вопросы по изменениям Git за выбранный период и нужным записям журнала. Учитывай новые файлы, изменения в индексе Git и ещё не добавленные в него правки. Неизвестную дату укажи явно. Недоступность Git или источника не означает отсутствие изменений.
3. Проверь выбранные важные утверждения по нужным фрагментам первичных источников. Архивы и полные отчёты читай только при необходимости. Если отсутствие новых изменений проверено, кратко сообщи это и закончи без записи отчёта в базу.
4. Найди открытые вопросы, устаревшие следующие действия, источники без полезного обобщения в wiki, слишком длинные страницы, незаписанные решения и пропущенные указатели в индексах или перечне источников.
5. Запусти доступные проверки: Windows — `scripts/kb_doctor.cmd` и `scripts/wiki_lint.cmd`; macOS/Linux — `python3 scripts/kb_doctor.py` и `python3 scripts/wiki_lint.py`.
6. Предложи не более пяти следующих действий. В `report-only` не меняй файлы и внешние системы. В разрешённом `writeback` используй `wiki/workflows/writeback.md` только для нового проверенного знания; повтор без новых данных ничего не добавляет.

## Результат

Один краткий отчёт в чате: состояние, замечания, до пяти действий, предложения
по сохранению выводов, выполненные проверки, уверенность и ограничения.
Этот промпт не создаёт расписание и не разрешает коммит или отправку в Git.

Не обходи весь raw без причины и не выноси лишние чувствительные сведения в
общие заметки. Предположения и неизвестное обозначай явно. Чтение или ссылка
не доказывают применение памяти, молчание — приёмку результата. Не исследуй
все журналы ради отсутствующих счётчиков. Если измерения доступны, разделяй
некэшированный вход, кэшированный вход и выход, указывая границы измерения.
