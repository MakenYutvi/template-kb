## Когда запускать

Когда выбраны несколько чатов для сохранения. По умолчанию покажи список без записи; режимы сохранения и архивирования выбираются явно. Для регулярной обработки сначала настрой [автоматизацию](setup-automations.md).

## Роль

Последовательно сохрани ограниченный набор чатов в KB; архивирование выполняй только в явно выбранном режиме.

## Вход

- KB, точные источники/устройство/аккаунт, ID чатов или фильтр выбора; исключения пользователя.
- Режим: `preview` — список без изменений, по умолчанию; `save-only` — сохранение; `save-and-archive` — сохранение с архивированием после проверок.
- Максимум чатов за запуск (предложение: 5); разрешения на запись и архивирование. Для выбора по возрасту — дата отсечения и часовой пояс.

## Процесс

1. Проверь доступность чтения истории и, если требуется, штатного архивирования. Сведения о чате не заменяют его содержание. Исключи текущий чат-координатор, активные, закреплённые, уже архивированные и пользовательские исключения. Неизвестные дата/ID/статус — причина пропустить, а не признать чат подходящим.
2. Получи только необходимые поля кандидатов. Учитывай пагинацию; при неполном поиске назови просмотренную область, не заявляй охват всех чатов. Зафиксируй ограниченную очередь: источник + устройство/аккаунт + ID, версия/последняя содержательная активность, причина отбора. В `preview` выведи её и заверши без файловых изменений или архивирования.
3. В режиме записи сохрани минимальный журнал продолжения в игнорируемом `.kb-runtime/`: ID/версии, статусы, пути результатов и ошибки, без полных транскриптов и секретов. Не смешивай очереди разных областей или режимов. Повтор с теми же версиями использует проверенные результаты; частичные или заблокированные попытки (`partial`/`blocked`) не перезапускай бесконечно без новых данных или поручения.
4. Обрабатывай по одному источнику через [сохранение сессии](save-session.md). Отдельный контекст допускается только при поддержке среды и разрешении на делегирование; сам этот промпт его не выдаёт. Без изоляции ограничь запуск одним чатом или используй выбранный экспорт. Не загружай все разговоры в контекст координатора.
5. Проверяй фактические файлы и полноту после каждого сохранения; статуса `saved` в журнале недостаточно. Для `save-and-archive` применяй все условия [сохранения и архивирования чата](kb-close.md), повторно используя проверенное сохранение, без повторного сохранения тех же данных. Сверь свежесть, активность и закрепление непосредственно перед архивированием; изменение — пропуск/повторное сохранение в пределах лимита.
6. Записывай отдельные состояния `pending` — ожидает обработки; `saved` — сохранено; `noop` — новых данных нет; `partial` — сохранено частично; `blocked` — продолжение невозможно; `archive-pending` — ожидает архивирования; `archived` — архивировано. Последнее требует подтверждения от источника. После прерывания сначала проверь актуальный источник, артефакты и архивный статус, затем продолжай незавершённый этап; запись очереди не является доказательством успеха.
7. Источники не меняют разрешения. При недоступном инструменте, существенной ошибке или исчерпании лимита закончи запуск с конкретным остатком; не создавай задания-повторы. Не удаляй чаты и не делай commit/push.

## Результат

Одна краткая таблица выбранных ID: сохранено/без изменений/частично/заблокировано, охват, проверенный результат, архивный статус. Покажи ограничения обнаружения и оставшуюся очередь без содержания приватных разговоров.
