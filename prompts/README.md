# Как выбрать промпт

Промпт — готовое задание для ИИ-агента. Выберите свою задачу ниже, откройте ссылку
и передайте агенту нужные материалы. Не нужно изучать или запускать весь каталог.

## Практические команды

Для начала чаще всего достаточно одного из этих запросов. Замените текст
в угловых скобках своими данными; сами скобки не нужны.

| Что хотите сделать | Что отправить агенту |
|---|---|
| Сохранить полезный результат текущего чата | `Выполни prompts/save-session.md. Источник: текущий доступный чат. Тема: <тема>.` |
| Продолжить старую задачу в новом чате | `Выполни prompts/resume-task.md для <задача или страница>. Режим brief: сначала восстанови контекст.` |
| Разобрать новый документ | `Выполни prompts/ingest-source.md для <путь к источнику в raw/>.` |
| Проверить готовый текст | `Выполни prompts/document-review.md для <файл>. Цель документа: <цель>.` |
| Проверить состояние базы за неделю | `Выполни prompts/weekly-review.md. Область: <тема>. Режим report-only — только отчёт.` |
| Настроить автоматизации | `Выполни prompts/setup-automations.md для текущей KB в режиме propose — предложи варианты.` |

Если агент читает файлы репозитория, достаточно такого запроса. Если вы работаете
в обычном веб-чате, скопируйте туда текст выбранного промпта и разрешённые
материалы. Модель без доступа к файлам может подготовить текст, но не должна
заявлять, что сохранила его в вашу базу.

Промпты можно использовать с разными моделями ИИ и на разных ОС. Чтение файлов,
Git, история чатов, архивирование и расписания требуют соответствующих инструментов.
Их отсутствие должно быть указано в результате, а не скрыто обещанием «готово».

двух версий. Ничего из этого не запускается каждый месяц само: расписание
настраивается отдельно.

## Что означают режимы

Имена режимов оставлены одинаковыми во всех промптах, чтобы готовые команды и
настроенные задания продолжали работать.

| Режим | Что делает |
|---|---|
| `brief` | Восстанавливает контекст без изменений; `continue` продолжает разрешённую работу |
| `report-only` | Возвращает отчёт; `writeback` сохраняет разрешённые проверенные выводы |
| `check` | Проверяет Git без изменений; `commit` сохраняет локальный коммит; `sync` также получает и отправляет изменения |
| `preview` | Показывает выбранные чаты; `save-only` сохраняет; `save-and-archive` также архивирует при выполнении проверок |
| `propose` | Предлагает автоматизации; `apply-selected` настраивает уже выбранные задания и параметры |
| `draft` / `apply` | В промпте сокращения: отдельный черновик / применение проверенного сокращения |
| `propose-only` / `apply-approved` | В ретроспективе: только предложения / применение уже выбранных изменений |
| `auto` / `discovery` / `draft` | В PRD: выбрать подходящий путь / уточнить основу / сразу написать черновик с явными пробелами |

Выбор промпта не разрешает любые действия. Проверка не означает согласия на
публикацию, а сохранение чата — на его архивирование. Повтор без новых данных
не должен создавать дубликаты. При отсутствии измерений или доказательств
результат остаётся неизвестным.

## Перенос из веб-чата

Запустите выбранный промпт переноса **в исходном веб-чате**. Он подготовит:

1. `КОРОТКАЯ КОМАНДА ДЛЯ АГЕНТА` — что сделать принимающему агенту.
2. `TRANSFER PAYLOAD` — сам передаваемый текст.

Передайте оба блока агенту с доступом к базе: сначала команду, затем текст или
файл с ним. Проверьте предложенное место сохранения. Подготовка этих блоков
ещё не означает запись в базу.

Историческое имя `web-gpt-global-context-to-kb-transfer.md` сохранено для
совместимости ссылок; GPT не обязателен. Недоступные сведения из других чатов
модель не должна придумывать. Копировать текст можно обычным способом на любой ОС.

## Формат

<details>
<summary>Для тех, кто добавляет или меняет промпты</summary>

Каждый файл содержит готовое задание, которое можно целиком передать агенту.
Используйте понятные разделы: когда запускать, роль, вход, результат и процесс.
Не добавляйте обязательные пути конкретного компьютера, имена проектов или
требования к одной модели. Такие сведения пользователь передаёт при запуске.

Служебные поля в начале файла не нужны. Для длительно используемых процедур
сохраняйте `Prompt Version` и `Prompt Changelog`, если от версии зависит поведение.
Имена файлов — латиницей с дефисами; существующие имена и значения режимов
не переименовывайте ради редакторской правки.

Обёртки приложений ссылаются на один основной файл промпта, а не хранят
расходящиеся копии. При обновлении своей базы сохраняйте локальные версии
промптов и согласовывайте нужные изменения. Новые задания не включаются сами.

</details>
